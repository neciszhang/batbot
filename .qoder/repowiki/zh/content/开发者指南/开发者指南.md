## 简介

## 消息系统架构

**新增** 消息系统架构是 BatBot 的核心基础设施，提供了异步消息传递、事件模型和消息总线的完整解决方案。该架构支持多通道消息处理，为未来的扩展奠定了坚实基础。

### 异步队列设计

AsyncQueue 是消息系统的核心组件，实现了生产者-消费者模式的异步队列。它通过 Promise 和回调函数的组合，确保消息的有序传递和高效的异步处理。

```mermaid
classDiagram
class AsyncQueue {
-queue : T[]
-waiters : ((value : T) => void)[]
+get() : Promise~T~
+put(item : T) : Promise~void~
+size : number
}
class Producer {
+produce() : void
}
class Consumer {
+consume() : void
}
AsyncQueue <|-- Producer : "生产者"
AsyncQueue <|-- Consumer : "消费者"
```

**核心特性**：
- **无阻塞获取**：当队列为空时，get() 方法返回 Promise，等待生产者放入消息
- **高效消息传递**：当有等待的消费者时，直接将消息传递给消费者，避免额外的队列存储
- **内存优化**：只有在没有等待消费者时才将消息存储在队列中

### 消息总线设计

MessageBus 作为消息系统的核心协调器，管理入站和出站消息队列，提供统一的消息发布和消费接口。

```mermaid

C->>MB : consumeOutbound()
MB->>MB : AsyncQueue.get()
MB-->>C : OutboundMessage
```

**核心功能**：
- **双向通信**：同时支持入站和出站消息处理
- **状态监控**：提供队列大小查询接口
- **异步处理**：完全基于 Promise 的异步消息处理

### 设计理念与实现细节

消息系统采用以下设计理念：

1. **解耦设计**：生产者和消费者通过消息总线解耦，无需直接通信
2. **异步优先**：所有操作都是异步的，避免阻塞主线程
3. **内存友好**：智能的队列管理，最小化内存占用
4. **扩展性强**：支持新的消息类型和通道类型轻松扩展

## 性能考虑
- 编译与打包
  - 使用 NodeNext 模块解析与模块系统，减少运行时兼容成本。
  - 严格模式开启，提升类型安全与潜在错误发现效率。
- I/O 与文件操作
  - 模板同步仅在首次初始化执行，避免重复 I/O。
  - 写入配置前确保目录存在，减少失败重试。
- 日志输出
  - 使用 ANSI 包装与宽度计算，避免长文本渲染异常导致的额外开销。
- **消息系统性能**
  - **内存优化**：AsyncQueue 采用智能队列管理，只有在需要时才存储消息
  - **异步处理**：完全基于 Promise 的异步模型，避免阻塞
